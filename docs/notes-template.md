# Lab 笔记模板

复制本模板到 `项目/notes/<lab>.md`，随做随写。**完成判定依赖本笔记**：测试通过 + 本笔记充实 + git 提交，三者齐备才把进度表改为「已完成」。

```markdown
# <Lab 名称>

- 状态：进行中
- 开始日期：YYYY-MM-DD
- 完成日期：
- 相关提交：

## 目标

用自己的话写清这个 lab 要解决什么问题、验收标准是什么。

## 设计决策

关键设计选择与理由，包括放弃的备选方案（例如 libco 用 setjmp/longjmp 还是 ucontext；pstree 先建树还是边扫描边打印）。

## 踩坑记录

| 现象 | 根因 | 解法 |
|---|---|---|
| | | |

调试过程用到的 gdb 命令、观察点、关键日志。

## 验证方法

如何证明实现正确：通过的测试、对拍对象、边界用例（空进程表、满队列、栈溢出检测等）。

## 可改进点

已知缺陷、性能问题、没想明白的地方，留给以后（或复习时）处理。

## 完成判定清单

- [ ] 官方/自带测试通过
- [ ] 本笔记的「踩坑记录」「验证方法」已写完
- [ ] 代码已 git 提交
- [ ] 根 README 进度表已更新
```

## 写作原则

- 记录 **为什么** 而不是复述代码；代码本身在 git 里。
- 踩坑记录写「现象 → 定位过程 → 根因 → 解法」，下次遇到同类问题能直接搜。
- 不追求篇幅，但「设计决策」和「验证方法」两节不能空。
